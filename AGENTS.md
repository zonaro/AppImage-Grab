# Orientações para agentes

- Monorepo Linux, Python stdlib + WebExtensions JS; sem dependências extras.
- Gear Lever é o backend, não recriar nem alterar banco/metadata internos dele.
- Extensão OFF por padrão; ON integra automaticamente downloads concluídos com extensão .AppImage. OFF não intercepta downloads.
- Segurança: não executar AppImages diretamente, nunca usar shell=True. No host, validar apenas a segurança do caminho recebido (absoluto, sufixo .AppImage, arquivo regular do usuário sem symlinks). Não validar assinatura ELF, MIME, magic bytes, tamanho mínimo, conteúdo, hash, arquitetura ou localização do resultado. Gear Lever decide o suporte ao arquivo. URLs de download selecionadas manualmente ainda devem ser verificadas quanto à origem pelo resolvedor; nunca inventar URL de updates.
- Não sobrescrever fonte de atualização já existente ou embutida. Usar Gear Lever CLI.
- Pasta final deve ser controlada por Gear Lever; nunca mover arquivos manualmente.
- Native host de uma solicitação por processo, comunicação JSON length-prefixed em stdin/stdout.
- Navegadores precisam de consentimento para instalação de extensões. Nunca utilizar políticas corporativas para fazer force-install.
- Atualizar README, .agents e testes quando mudar contrato, CLI ou fluxos.
- Testes: python3 -m unittest discover -s tests -v; node --check extension/common/background.js; bash -n install.sh uninstall.sh scripts/build-extensions.sh.

- O resolvedor de links deve continuar oferecendo escolhas de arquivo/arquitetura apenas quando o release é verificável, mas a integração automática NÃO detecta fontes, NÃO gera wildcards e NÃO chama --set-update-source. Fontes de atualização são responsabilidade do Gear Lever ou de edição explícita do usuário no manager.
- Interface web: Native Messaging API com ações allowlisted, confirmação explícita e path conferido na lista do Gear Lever; atualizações não podem forçar execução de apps abertos.
- Testes devem incluir novas rotas de gestão e carregamento dos recursos `manager.html`/`native-client.js`.

- The installer builds unpacked extension directories ONLY: `dist/chromium` and `dist/firefox`. No CRX or XPI packaging. Never force-install or alter browser profiles.
- The local HTML guide is generated by `scripts/generate_install_guide.py` using `scripts/install-guide-template.html`. Use absolute real paths, safe JSON escaping and buttons to copy paths/extension page URLs. Detect browsers via `register_hosts.BROWSERS`.
- The installer should open the local HTML guide AND launch the detected default browser's extensions page directly via that browser's executable and internal URL (e.g. Edge with `edge://extensions/`, Firefox with `about:debugging#/runtime/this-firefox`). Never call xdg-open or follow a `file://` link for internal schemes. Use `xdg-settings`/ `xdg-mime` only to discover the default browser; if unknown, open one supported detected browser, never all installed browsers. `GLG_OPEN_BROWSER=0` and headless environments skip both launches. The HTML guide remains copy-only for internal addresses; manual extension activation is always required.
- Keep README.md fully in English. Landing remains PT-BR/EN/ES; local guide supports the same languages.
- Remove obsolete dist/packages artifacts when updating, but never delete keys from previous releases without explicit consent.
- Keep extension ON/OFF OFF by default; install script does not modify browser extension state.

- The Git SHA of main is the only application build identifier, embedded by scripts/build-extensions.sh into version.json and build-revision.js for both extension flavors. The installer must fetch the newest main even if invoked from an old local checkout.
- Browser manifests under `extension/` are templates. During `scripts/build-extensions.sh`, `scripts/manifest_version.py` stamps the same version for Chromium and Firefox from the commit's committer timestamp, preserving its timezone: numeric `YY.DDD.HHmm` without forbidden leading zeros in `version`, and zero-padded display value in `version_name`. The Git SHA remains the authoritative build identifier. Do not manually bump release versions or stamp wall-clock build time.
- bridge/host.py getVersion exposes installed version.json without initializing Gear Lever. Write installed revision LAST after successful installation.
- The extension periodically compares GitHub commits/main against its embedded commit and host commit; badge NEW and UI alerts do not run shell scripts and must not toggle ON/OFF.
- Keep README.md English and do not claim locally packaged CRX/XPI can be silently updated inside a browser.

- Local CRX3 packages are no longer created or distributed. Install browser extensions manually: Load unpacked on Chromium-family browsers, Load Temporary Add-on with manifest.json on Firefox.

- An update manager name is not evidence of an available update. The browser Update button appears only for exact paths returned by Gear Lever --list-updates --json, and the Python host rechecks that command immediately before --update.
- The public Gear Lever list-installed JSON omits existing source parameter values. bridge/source_config.py reads the selected Gear Lever's gearlever.conf read-only (Flatpak or native), keyed by MD5 of the exact installed AppImage path. Do NOT write the INI file.
- Preserve pre-existing sources: embedded sources are read-only; if existing config cannot be verified, block replacement/removal; unsupported managers must not be silently mapped to GithubUpdater.
- Regression tests: tests/test_source_config.py and tests/test_manager.py. Maintain exact path matching and fail-closed behavior on offline/missing config.

- When editing link imports: never download arbitrary URL schemes or hosts; trust only explicit provider release assets and fixed GitHub/GitLab/Codeberg APIs. Asset/architecture selection followed by a direct Install click establishes user intent without a second dialog. Browser background must revalidate the selected asset.
- A integração automática deve confiar somente no retorno da CLI pública `gearlever --integrate <path> -y`. Código de saída 0 é sucesso; `This AppImage is already integrated` significa já processado, sem nova notificação. Erros (retorno não zero) são registrados em History. Não exigir installedPath nem --list-installed para confirmar. O modo ON/OFF não bloqueia imports manuais.
- Nunca revalidar cópia instalada, comparar hashes/tamanhos, consultar a lista de instalados ou tentar inferir destinos no fluxo `integrate`. Se Gear Lever informar caminho na saída, usá-lo apenas para mostrar ao usuário. Sem caminho na saída, o sucesso continua válido (filename original para notificação). Não registrar fonte de atualização automaticamente e não modificar fontes preexistentes.
- Preserve icon assets from `extension/common/icons` in both unpacked extension builds and use matching favicon under `docs/assets/favicon.png`.

- On supported GitHub/GitLab/Codeberg repository/release tabs, `page-offers.js` conservatively canonicalizes the URL. `page-offer-background.js` resolves releases through the existing Native Messaging host and offers install notifications only when assets are confirmed. Never introspect page content or visit unsupported hosts.
- Passive browser push notifications are separate from download ON/OFF and can be disabled with `suggestionsEnabled` in popup. Persist a per-repository 24h cooldown and do not spam repeated tab activations.
- Popup/manager/store install requires asset/architecture selection and a direct user click on Install/Download; do not open a second `window.confirm` dialog for installation. Notification buttons only open a prefilled manager; navigating or clicking a notification must never auto-download. `startManagedDownload` must still revalidate the chosen asset via native resolver. Keep confirmations for updates, removals and update-source modifications.
- Any new permissions must be narrow, disclosed in README and covered by tests; `tabs` is only used to access supported URL metadata.
- Include `page-offers.js`, `page-offer-background.js` in both Chromium (importScripts) and Firefox (background.scripts) as well as unpacked builds. Test with `node scripts/test-page-offers.mjs`.

- Notification delivery is local WebExtensions API only: no remote push service. `notifications.js` is shared by the Chromium service worker and Firefox background scripts; keep it loaded before page offers/background. Never equate accepted `notifications.create` with an OS-displayed toast.
- Notification preferences are separate from automatic download ON/OFF. Preserve the legacy `suggestionsEnabled` setting, bound repository cooldown to 24h, and keep local history small and free of full paths, credentials, and private URLs.
- AppImage update alerts require exact paths confirmed by both Gear Lever `listUpdates` and `listInstalled` (not inferred from a manager name); do not reset deduplication on offline failures. Notification clicks only open the manager, never trigger installation/update.
- Test notifications with `node scripts/test-notifications.mjs`, `node scripts/test-integration-notifications.mjs`, and `node scripts/test-page-offers.mjs`. Keep notification category text localized via the shared i18n registry.

- Persist browser-local installation history (max 200 per-download entries) via `activity-log.js` loaded in Firefox scripts and Chromium `importScripts`; preserve real error details while redacting full paths, URLs and credentials. No telemetry, remote push or automatic replay of failed installations.
- `manager.html` History view is strictly read-only except clearing browser history after user confirmation. `getHostLog` must only read the fixed bridge-owned `STATE_DIR/host.log` (regular file owned by the user); bound reads and return redacted warnings/errors, never raw arbitrary paths or Gear Lever private configuration. A notification click may open `manager.html?view=history`, but cannot install anything.
- Validate history with `node scripts/test-activity-history.mjs`, backend host-log tests and existing integration notification regressions. Clear browser history without deleting the host log.
